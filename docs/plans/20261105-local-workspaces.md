# Plan: 20261105-local-workspaces
Status: Approved; implementation completed 2026-11-05. Playwright E2E is blocked by the macOS Codex sandbox.
Linked Requirement: REQ-WORKSPACE-001

**Goal:** Deliver local workspace creation, listing, and read-only details, without implying that the bundled demo belongs to an empty workspace.

**Architecture:** Pure domain rules and use cases call a `WorkspaceStore` port. A filesystem adapter owns manifest and path handling; FastAPI exposes the contract; React pages use a typed API client. This phase adds no existing-workspace mutation, import, snapshot, or assessment.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, pathlib/stdlib JSON, React, TypeScript, Vite, Arco Design React, Playwright.

**Spec:** `docs/features/REQ-WORKSPACE-001-local-workspaces.md` (phase 1 of v0.18 WS-01). The first importer after this phase is restricted JSON, as selected by the product owner; its input profile is outside this plan.

## Global Constraints

- Unknown evidence or failed/unavailable validation must not become verified Qualified.
- Data completeness, decision status and verification/assurance status remain separate.
- No workspace operation in this phase creates an active snapshot, a mapping approval, a validation result, or a quality decision.
- Bind only to loopback; validate Host and require an allowed Origin on workspace creation requests.
- The frontend never receives or submits filesystem paths. Workspace IDs are canonical UUIDs generated by the server.
- Pure domain code imports neither FastAPI, RDFLib, nor filesystem adapters.
- Do not claim checks that were not run; the E2E gate remains `blocked` if the documented macOS browser restriction occurs in the sandbox.

## Review Focus

- Empty, whitespace-only, control-character, lone-surrogate, and over-80-codepoint names: reject with a stable validation error; preserve valid Unicode after trimming.
- Corrupt, unsupported, or ID-mismatched manifests: list the workspace as unavailable without stopping other entries, exposing file contents, or overwriting data.
- Symlinked workspace directories and `manifest.json`: never follow them; do not expose their targets.
- Missing, relative, or platform-specific `SDLC_QE_DATA_DIR`: fail clearly or resolve deterministically without writing during app startup or reads.
- POST with missing or untrusted Origin and any request with an untrusted Host: reject; allowed UI-origin creation succeeds.

## 目标、现状与预期用户价值

实现本地工作区的创建、列表和只读详情，为后续本地数据导入提供安全的存储边界。当前前端固定展示仓库示例，后端只有只读 metadata API；用户工作区尚不存在。空工作区明确显示“无导入数据 / 无活动快照”。本计划不实现全局当前工作区切换，也不声称完成完整 WS-01；单写者锁必须在首个既有工作区写入功能之前交付。用户已选定 JSON 为后续首个导入格式，其输入 profile 与限制另立计划。

## 技术方案与架构边界

- 采用 domain → application use cases → `WorkspaceStore` port → filesystem adapter → FastAPI router 分层；领域层不依赖 FastAPI、RDFLib 或文件系统。
- 数据根目录只由服务端配置：非空 `SDLC_QE_DATA_DIR` 优先；未设置或值为空时 macOS 使用 `~/Library/Application Support/SDLC-QE Ontology Workbench`，Windows 使用 `%LOCALAPPDATA%/SDLC-QE Ontology Workbench`（变量缺失或非绝对路径时 `~/AppData/Local/SDLC-QE Ontology Workbench`），其他系统使用绝对路径 `$XDG_DATA_HOME/sdlc-qe-ontology-workbench`，否则使用 `~/.local/share/sdlc-qe-ontology-workbench`。`SDLC_QE_DATA_DIR` 支持 `~` 展开；相对覆盖值相对服务进程工作目录解析。解析配置不触发文件写入。
- 每个工作区用服务端生成的规范 UUID，保存到 `<data-root>/workspaces/<uuid>/manifest.json`。manifest v1 必须且只包含 `schemaVersion`（整数 `1`）、`workspaceId`（与目录名一致）、`name`（已规范化）、`createdAt`（UTC RFC 3339 字符串）、`activeSnapshotId`（`null`）。缺字段、未知字段、重复键、类型错误、未知版本、超过 64 KiB 或 ID 不匹配都按损坏 manifest 处理。列表只扫描小写规范 UUID 目录；创建时间倒序，同一时间按 UUID 升序。
- 创建时先在 `workspaces/` 下用唯一名称建临时目录，在其中完整写入 manifest，再以同卷目录 rename 发布。若生成的 UUID 目标已存在则重新生成 UUID，不能覆盖已有目标。创建失败时只清理本次创建的临时目录；崩溃遗留临时目录以隐藏前缀命名，列表忽略它，不自动清理。
- POSIX 下应用新建的数据根目录、`workspaces/`、工作区目录权限为 `0700`，manifest 为 `0600`；不会修改已有目录权限。其他平台使用当前用户默认 ACL。存储根按配置 canonicalize；若 `workspaces/` 是符号链接则报告存储不可用。工作区目录及 manifest 用 `lstat` 检查普通目录/文件，并用 no-follow 打开 manifest（平台支持时），不跟随符号链接。
- 名称先按 Unicode whitespace `strip()`，长度为 1–80 个 Unicode code point，拒绝 Unicode 类别 `Cc` 控制字符和无法编码为 UTF-8 的孤立 surrogate（`Cs`）；同名允许，UUID 保证身份唯一。
- 提供 `POST /api/v1/workspaces`（201）、`GET /api/v1/workspaces`、`GET /api/v1/workspaces/{workspaceId}`。列表返回 `{workspaces: [...]}`。可用项字段为 `workspaceId`, `name`, `createdAt`, `status: "empty"`, `activeSnapshotId: null`；损坏项字段为 `workspaceId`, `name: null`, `createdAt: null`, `status: "corrupt"`, `issueCode: "workspace_manifest_unavailable"`。`GET` 详情只返回相同的有效工作区对象，不存在快照数据。列表只公开工作区 metadata；本阶段没有跨工作区的数据集读取/写入 API。
- 无效/未知 ID 返回 404，错误 body 为 `{"detail":{"code":"workspace_not_found"}}`；无效名称返回 422 与 `workspace_name_invalid`；损坏详情返回 409 与 `workspace_manifest_unavailable`；存储 I/O 不可用返回 503 与 `workspace_storage_unavailable`。所有错误 body 都使用 `{"detail":{"code":"..."}}`，不包含路径、原始 manifest 或异常正文。Pydantic 对缺字段/非 JSON 请求体的默认 422 只用于请求形状错误，不替代领域名称错误码。
- `POST` 必须带 `Origin` 且只接受现有浏览器 allowlist；`CORSMiddleware` 允许 `GET`、`POST` 和 JSON `Content-Type`。保留当前 loopback Host 检查；不开放其他网络绑定。
- 增加主导航和移动导航的“工作区”入口、`/workspaces` 列表/创建页和 `/workspaces/:workspaceId` 只读详情页。损坏项可见但不能打开。全局 shell 将数据标识明确写为“仓库示例 · 只读 / Bundled example · read only”，不再称为“当前工作区”；打开工作区详情不改变全局数据源。现有 Overview / Ontology / Analysis 继续标为 bundled demo。
- 移动端五项导航允许横向滚动，不得挤压或溢出页面；创建表单和 corrupt 状态可键盘访问。
- `GET` 和 app startup 不创建数据根目录。E2E 一律使用临时 `SDLC_QE_DATA_DIR`，结束后只清理由 E2E 脚本创建的临时目录。

## 时序图或数据流

`Workspace page → typed API client → FastAPI route → application use case → WorkspaceStore port → filesystem adapter → local data root`

创建时 adapter 生成 UUID，在同文件系统临时目录写入并校验 manifest 后 rename 到正式目录；失败不发布半成品。读取仅接受规范 UUID 路径，不跟随 workspace 或 manifest 符号链接。工作区已有内容没有写入 API，所以本阶段不需要锁；后续 JSON 导入写入计划必须先实现单写者锁和跨工作区隔离。

## 风险、回滚、可观测证据

- The first user-created workspace writes to a configured local data root. Tests inject temporary directories. No operation deletes, migrates, or overwrites an existing workspace.
- Atomic publication requires temp and destination directories on the same filesystem; the adapter creates temp directories as children of `workspaces/`.
- Corrupt/unsupported manifests remain untouched and are reported by stable code without absolute paths or raw contents.
- Rollback removes code only; it never removes user workspace files. QA records contain only commands run in this checkout.
