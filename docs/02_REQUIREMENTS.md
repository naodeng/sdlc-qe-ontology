# 产品需求与边界（Draft v0.1）

## 用户与 Jobs-to-be-Done
| 用户 | 主要任务 | 成功表现 |
|---|---|---|
| QA 工程师 | 从需求追踪到测试证据 | 找到未满足的验证义务和来源 |
| 开发工程师 | 分析代码变更质量影响 | 查看受影响组件与测试义务 |
| 技术负责人 | 审查质量门禁 | 查看有证据的风险和未知项 |
| Agent/工具作者 | 查询统一语义 | 使用稳定的类、关系与只读查询接口 |

## 功能需求
| ID | 需求 | 优先级 | 可验证验收条件 |
|---|---|---|---|
| FR-01 | core/sdlc/qe 模块化本体 | P0 | 可独立解析，导入关系无循环 |
| FR-02 | 需求—测试义务—执行—证据链 | P0 | SPARQL 返回正确链路及缺口 |
| FR-03 | PR/组件/需求影响关联 | P0 | 标注样本的关系可查询 |
| FR-04 | SHACL 数据验证 | P0 | 正例通过，缺失字段与类型反例失败 |
| FR-05 | 双语标签与术语词典 | P0 | 核心概念具备中英名称与定义 |
| FR-06 | 本体一致性与版本兼容测试 | P0 | CI 可执行并报告结果 |
| FR-07 | 参考软件交付数据集 | P1 | 无隐私数据，端到端可复现 |
| FR-08 | 变更影响 CLI | P1 | 输入示例变更输出证据化结果 |
| FR-09 | Agent 只读查询适配 | P2 | 不允许默认写操作且有审计 |

## 非功能需求
可本地运行；可复现；确定性验证；不强制云服务；稳定 URI；中英文文档；模型演进可追踪；许可证清晰；样例不包含真实用户数据。

## 明确非目标
行业业务本体；自动化需求真伪判定；自动生成足够覆盖的全部测试；替代 GitHub/Jira；将 AI 生成内容当作事实；无人工参与的发布批准。

## 关键术语
`TestObligation` = 基于需求、风险或规则需要获得的验证义务；`QualityClaim` = 有待证据支持的质量主张；`TestEvidence` = 带来源、时间、执行环境和结果的验证材料。

## 关键待定决策
证据可信度分级、OWL profile、实体 ID 对齐策略、历史版本兼容边界、基准数据集规模，须在 Spike 阶段确定。
