# TDD / 质量门禁

## RED → GREEN → REFACTOR
1. 在变更前添加针对需求 ID 的失败用例，记录 RED 原因（应为目标行为断言失败，非依赖缺失）。
2. 最小实现至 GREEN，然后重构，确保用例仍通过。
3. 执行单元测试、契约/组件测试、SHACL、SPARQL CQ、golden 规则、导入负例、安全回归和 Playwright E2E；未执行的门禁必须标记 `not_run`。

## Gate 0 / 1 / 2
- G0：需求、ADR、风险和预期测试获批。
- G1：单元 + API 契约 + 本体/SHACL + 字段映射校验通过。
- G2：E2E、恶意输入、快照回滚、可访问性和文档同步通过后才能宣称 MVP Ready。

## 强制负例
- 未确认 mapping / 确认后源文件变化；不匹配 Build、缺时间戳、SHACL 未执行、重复 ID、非法 RDF、错误来源、快照冲突、部分写入、并发提交、长链图截断。
- 必须明确测试运行环境、命令、结果、日志/报告位置；禁止把测试设计当作测试已通过。
